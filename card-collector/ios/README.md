# 아이폰 카드 결제 알림 수집

## 여행 웹으로 현대카드 승인 보내기

1. 팀 웹에서 **여행 → 카드 지출 → 휴대폰 수집기 연결**을 열고 해당 결제자의 연결 정보를 발급한다. 휴대폰에서 접속할 수 있는 전체 HTTPS 주소가 필요하다. 주소의 경로는 `/api/collector/events`다.
2. 아이폰에서 [NTrip 현대카드 전송](배포용/NTrip%20현대카드%20전송.shortcut)을 다운로드해 파일 앱에서 연다. 추가할 때 HTTPS 주소와 Bearer 토큰 **값**을 입력한다. 이 개인화된 단축어에는 토큰이 들어 있으므로 팀원에게는 위의 빈 설정 배포본을 공유한다.
   GitHub 파일 페이지에서는 **Download raw file**을 누른다. 파일 이름의 `.shortcut` 확장자를 유지한다.

3. 처음에는 잠금을 해제하고 단축어를 직접 실행한다. 테스트 여행에 아래 가상 문자를 입력한 뒤 단축어의 파일 저장·해당 서버 연결 요청을 허용한다. 웹의 **수신한 카드 알림**에서 `1,400 KRW · 예시마트샘플점`을 확인하고 **지출 검토 → 카드 지출 등록**을 선택한다.

   ```text
   [Web발신]
   현대 넥슨 승인
   가*나
   1,400원 일시불
   03/12 08:25
   예시마트샘플점
   누적23,700원
   ```

4. 자동으로 받으려면 **단축어 → 자동화 → 메시지**에서 현대카드 발신자와 **즉시 실행**을 선택한다. **단축어 실행 → NTrip 현대카드 전송**의 입력으로 수신 메시지의 **본문**을 연결한다. 이 버전은 현대 넥슨 국내 일시불 승인 문자 양식을 처리한다. 카드 앱 푸시 및 다른 양식은 아래 별도 설정을 참고한다.
5. 전송 전에 매 건을 **파일 앱 → Shortcuts**의 `NTrip-〈UUID〉.txt`에 저장한다. 이 폴더는 기기 설정에 따라 iCloud Drive에 표시될 수 있다. 네트워크 오류나 응답 유실 시 해당 파일을 열어 **내용 전체**를 복사한 뒤 같은 단축어를 직접 실행해 붙여넣는다. 기존 UUID와 수신 시각으로 재시도한다. 파일 공유 시트에서 단축어로 전달할 수도 있다. 원문을 새로 입력하면 새 이벤트가 된다. 다른 서버나 다른 결제자의 토큰으로 만든 파일은 재전송 대상에서 제외된다. 서버 확인 뒤에는 해당 파일을 직접 삭제할 수 있다.

서버가 같은 이벤트 UUID로 응답하면 성공 알림이 뜬다. 아이폰이 실제 채팅+를 받을 때의 자동 실행·잠금 상태 동작은 통신사 회선이 있는 실기기에서 확인한다. [Apple의 메시지 자동화](https://support.apple.com/guide/shortcuts/apdd711f9dff/ios)

전송 단축어의 재현 및 검사 명령은 다음과 같다. 빌더는 배포 전 설정이 비어 있는 원본을 만든다. 테스트는 아래 검증 도구와 같은 Windows ICU·`cryptography`·`lzfse`를 사용하며 서명본에 들어 있는 동작으로 가상 파일 저장, 재전송, 서버 응답을 검사한다.

```powershell
python -X utf8 card-collector/ios/build_sender.py
python -X utf8 card-collector/ios/test_sender.py
```

## 서버 없이 현대 넥슨 승인 확인하기

[서명된 단축어 파일](배포용/현대카드%20승인%20확인.shortcut)을 아이폰의 파일 앱에서 열어 추가한다. 처음에는 단축어를 직접 실행하고 기본 예문을 그대로 확인한다. 기대 결과는 **2,300원 · 테스트마트**다. 현대 넥슨 국내 일시불 승인 원문이나 한 줄 복사본을 입력하면 결제 금액과 가맹점을 표시한다. 이 배포본은 로컬 화면·알림 확인용이다.

자동 수신은 현대카드 발신자를 선택한 메시지 자동화에서 **수신한 메시지의 콘텐츠**를 이 단축어의 입력으로 전달한다. 다음 승인 때 단축어를 누르지 않아도 결과 알림이 나타나는지 확인한다. 잠금 상태에서도 사용할 경우 잠금 화면에서 별도로 한 건을 확인한다. 기업 RCS의 실제 도착과 실행 여부는 해당 통신사 회선·아이폰에서 시험해야 한다. 다음 절에서는 다른 카드 문구와 앱 푸시용 단축어를 구성하는 방법을 다룬다.

실물 카드로 결제한 뒤 카드사가 보내는 문구를 기본 **단축어**에서 처리한다. iOS 26은 카드사 문자, iOS 27은 카드사 문자와 선택한 카드사 앱 푸시를 연결할 수 있다. 팀 앱을 App Store에 배포할 필요는 없다. 아래 설정은 기기에서 직접 만드는 시연용이며, 실제 아이폰에서의 수신·잠금·전송은 아직 검증 전이다. [Apple의 iOS 26 메시지 트리거](https://support.apple.com/en-asia/guide/shortcuts/apdd711f9dff/9.0/ios/26) · [Apple의 iOS 27 단축어 변경 사항](https://support.apple.com/en-us/149045)

```powershell
python -X utf8 card-collector/ios/demo_shortcut.py
```

배포본 자체를 검사하려면 `icu.dll`이 있는 Windows에서 다음을 실행한다. 첫 검사는 Apple 인증서 체인과 서명을 확인하고 배포본 안의 동작을 원본과 대조한다. 두 번째 검사는 같은 배포본의 정규식과 수동 입력·자동 수신 분기를 정상 예문 12개와 제외 예문 19개로 시험한다.

```powershell

python -X utf8 card-collector/tests/verify_ios_archive.py
python -X utf8 card-collector/tests/ios_shortcut_cases.py
```

Apple의 iOS Simulator는 Mac의 Xcode에 포함된다. Mac에서 개발용 앱에 모의 푸시를 넣는 기능도 있지만, 현대카드가 등록된 번호로 기업 RCS를 보내거나 현대카드 앱에 승인 푸시를 보내는 과정은 해당 서비스에 연결된 기기에서 확인해야 한다. [Apple의 Xcode 시스템 요구 사항](https://developer.apple.com/xcode/system-requirements/) · [Apple의 시뮬레이터 푸시 설명](https://developer.apple.com/documentation/xcode-release-notes/xcode-14-release-notes)

현대카드 승인을 받는 팀원 한 명의 아이폰으로 실제 수신을 검증할 수 있다. 메시지 경로는 **설정 → 앱 → 메시지 → RCS 메시지**에서 RCS와 비즈니스 RCS 수신을 켜고, 현대카드의 다음 승인 알림이 올 때 단축어가 생성한 JSON 파일을 확인한다. 잠금 상태는 먼저 잠금 해제 상태에서 저장 권한을 허용한 뒤 시험한다. 카드 앱 푸시 경로는 iOS 27에서 현대카드 앱을 선택하고 실제 푸시 본문에 금액·가맹점이 담기는지도 확인한다. 다른 휴대폰에서 같은 문구를 보내는 시험은 일반 발신자의 메시지 수신 경로까지 검증한다. [Apple의 비즈니스 RCS 설정](https://support.apple.com/ko-kr/122195) · [Apple의 앱 알림 자동화](https://support.apple.com/en-us/149045)

가상 카드의 해외 결제 데모에는 아래 **합성 예시**를 사용한다.

```text
[데모카드] 해외승인 JPY 3,200 가맹점: SORA MART 승인번호: 00123456
```

## 현대 넥슨 일시불 승인 문자 적용

1. 아래 1·2절을 따라 만든 `카드 이벤트 만들기`를 복제해 `현대 넥슨 문자 이벤트`로 이름 짓는다. **메시지 자동화** 하나에서 발신자를 실제 현대카드 발신 연락처로 지정한다. `source: message`, `body: 수신한 메시지의 콘텐츠` 두 항목을 담은 사전을 `현대 넥슨 문자 이벤트`에 넘긴다. 발신자 선택이 되지 않는 기업 RCS는 이 경로에서 보류한다.
2. 복제한 단축어의 입력 검사에서 `source`가 정확히 `message`일 때만 계속한다. 2절 3번 `텍스트 일치`의 패턴을 [현대 넥슨 문자 정규식](hyundai-nexon-message-pattern.txt) 한 줄로 교체한다. 일치 결과가 비어 있으면 즉시 중단한다. 선택한 카드사 발신자와 일치하는 문구가 모두 필요하다. 현대카드 앱 푸시에는 이 규칙을 연결하지 않는다.
3. 2절 4번의 그룹 추출 동작을 두 개로 바꾼다. **그룹 1**은 `원 일시불` 앞 결제액이다. `텍스트 대치`로 쉼표를 지우면 `"1400"`이다. **그룹 2**는 일시 다음 줄의 가맹점 `예시마트샘플점`이다. 둘 다 텍스트로 유지한다. 이름, 월/일 시각, 마지막 줄의 누적액은 캡처 그룹에 들어가지 않는다.
4. 2절 6번 JSON에서 `issuer`를 `현대카드`, `event_type`을 `approval`, `currency`를 `KRW`로 고정한다. `amount`와 `merchant`는 그룹 1·2의 결과를 넣는다. 승인번호가 없고 거래 시각에 연도·시간대가 없으므로 `approval_ref`와 `occurred_at`에는 JSON `null`을 넣는다. `message_format`도 `null`로 둔다. 화면에서 RCS로 표시돼도 단축어에 전달된 값만으로 전송 방식을 판별할 수 없다. `received_at`과 `event_id` 및 재전송 절차는 2·3절과 같다.
5. 먼저 `훑어보기`에서 결제액 **1,400원**과 가맹점만 추출되고 누적액·카드회원 이름이 빠지는지 확인한다. 이 규칙은 국내 원화 일시불 승인 한 양식에 맞췄다. 취소·할부·해외 승인·다른 카드 상품에는 별도 예시가 필요하다. 아이폰이 실제 현대카드 기업 RCS 도착 시 이 자동화를 실행하는지도 별도로 시험해야 한다.

## 1. 수신 경로 설정

먼저 일반 단축어 하나를 만들고 이름을 `카드 이벤트 만들기`로 정한다. 아래 자동화에는 각각 `사전(Dictionary)`과 `단축어 실행(Run Shortcut)` 두 동작을 둔다. 사전에 `source`, `body`라는 **텍스트 키**를 만들고, 아래 값을 채운 뒤 **사전 전체**를 `카드 이벤트 만들기`의 입력으로 지정한다. 카드사마다 자동화를 따로 지정한다.

| 기기·경로 | 트리거에서 선택 | `source`와 `body` |
|---|---|---|
| iOS 26 문자 | `단축어 → 자동화 → + → 메시지`, 보낸 사람에 카드사 발신 번호를 저장한 연락처 지정 → `즉시 실행` → 새 빈 자동화 | `message`와 `단축어 입력(Shortcut Input) → 콘텐츠(Content)` |
| iOS 27 문자 | `단축어 → 보관함 → 자동화 → +`, 편집기에서 `메시지를 받을 때` → 발신자를 해당 카드사로 설정 → 자동화 켜기 | `message`와 **트리거의** `메시지(Message) → 콘텐츠(Content)` |
| iOS 27 앱 푸시 | 같은 화면에서 `알림을 받을 때` → 카드사 앱 한 개 선택 → 자동화 켜기 | `app_push`와 **트리거의** `알림(Notification) → 본문(Body)`. 데모 제목이 `[데모카드]`이면 `텍스트` 동작에 `제목(Title)`과 `본문` 변수를 줄바꿈으로 연결해도 된다. |

파란 변수 토큰을 선택해야 실제 수신 값이 들어간다. iOS 26에서 앱 푸시만 오는 카드 사용자가 시연에 참여하려면 카드사의 승인 문자 서비스를 켜거나 웹에서 직접 입력한다. iOS 27이라도 카드사 앱이 미리보기에 결제 정보를 싣지 않으면 금액을 복원할 수 없다. 문자 자동화에서 SMS·MMS·RCS 구분값을 확인하지 못하면 `message_format`은 `null`이다. 해당 카드사·통신사의 RCS가 이 트리거를 실행하는지는 실제 수신으로 확인해야 한다. [iOS 26 메시지 설정 화면](https://trackexpenses.app/videos/sms-setup-ios26.html) · [iOS 27 메시지 설정 화면](https://trackexpenses.app/videos/sms-setup-ios27.html) · [알림 제목·본문 선택 화면](https://spenti.app/blog/bank-notifications-to-expenses/)

## 2. `카드 이벤트 만들기` 동작 순서

1. 첫 동작에서 `현재 날짜`를 보관한다. 트리거가 실제 수신 시각을 제공하면 그 시각을 우선 사용한다. 그렇지 않으면 이 자동화가 시작된 시각을 `received_at`의 근사값으로 쓴다. `날짜 포맷 지정 → 사용자 설정`에 `yyyy-MM-dd'T'HH:mm:ssXXX`를 입력한다. 여행지와 무관하게 시간대가 붙는다. 거래 시각이 본문에 없으면 `occurred_at`은 `null`이다. [Apple 날짜 포맷](https://support.apple.com/guide/shortcuts/custom-date-formats-apd8d9b19184/9.0/ios/26)
2. `사전 값 가져오기`로 **단축어 입력**의 `source`와 `body`를 각각 얻는다. `source`가 `message` 또는 `app_push`일 때만 계속한다. 수신 경로를 선택한 자동화에 맞춰 카드사 이름을 고정한다. 이 예시에서는 `데모카드`다.
3. `텍스트 일치(Match Text)`의 입력에 `body`를 연결하고, 패턴에 [demo-pattern.txt](demo-pattern.txt)의 한 줄을 붙인다. 일치한 항목이 없으면 `이 단축어 중단`. 전체 입력을 검사하므로 인증번호·승인거절·잔액 안내·복수 금액·미지원 문구는 전송되지 않는다. 승인문 끝에 누적액이 추가된 경우에도 보류한다. 해당 카드사 양식을 확인한 뒤 지원 범위를 늘린다.
4. `일치하는 텍스트에서 그룹 가져오기(Get Group from Matched Text)`로 아래 값을 읽는다. 같은 **일치 결과**를 각 동작의 입력으로 다시 선택한다.

   | 그룹 | JSON 값 |
   |---|---|
   | 1 | `해외승인` → `approval`, `해외승인취소` → `cancel` |
   | 2 · 3 | 통화 `JPY`, 금액은 쉼표를 지운 **텍스트**. 취소도 양수 |
   | 4 · 5 | 가맹점과 승인번호. 빠진 값은 JSON `null`. 승인번호 `00123456`은 텍스트로 유지 |

5. `event_id`는 새 수신 건마다 UUID v4를 한 번 만든다. 기본 동작만으로 만들려면 `텍스트(0123456789abcdef) → 텍스트 분할(각 문자)`의 결과를 보관한다. `32번 반복`의 마지막 동작으로 **그 문자 목록에서** `목록에서 항목 가져오기 → 임의 항목`을 실행한다. 반복 결과를 `텍스트 결합`에서 구분자 없이 이어 붙인다. 별도로 `89ab`를 각 문자로 나눈 뒤 임의 항목 하나를 골라 `variant`로 보관한다. 32자리 문자열에 `텍스트 대치 → 정규 표현식`을 켜고 `^(.{8})(.{4}).(.{3}).(.{3})(.{12})$`를 `$1-$2-4$3-〈variant〉$4-$5`로 바꾼다. `〈variant〉` 위치에는 선택한 변수 토큰을 넣는다. [Apple의 임의 항목 선택 동작](https://support.apple.com/guide/shortcuts/use-list-actions-apd4dcacc115/9.0/ios/26)
6. `텍스트` 동작에 아래 JSON을 넣는다. `〈 〉` 전체를 앞에서 만든 **변수 토큰**으로 교체한다. `가맹점JSON`·`승인번호JSON`에는 값이 있으면 `텍스트` 동작으로 큰따옴표를 양쪽에 붙이고 없으면 네 글자 `null`을 담는다. 데모 정규식은 이 두 값에 큰따옴표·역슬래시·줄바꿈을 허용하지 않는다. 실제 카드 양식에서 허용 문자를 넓힐 때는 JSON 직렬화도 함께 변경한다.

   ```jsonc
   {
     "event_id": "〈event_id〉",
     "source": "〈source〉",
     "message_format": null,
     "issuer": "데모카드",
     "event_type": "〈event_type〉",
     "amount": "〈쉼표 없는 금액〉",
     "currency": "〈통화〉",
     "merchant": 〈가맹점JSON〉,
     "approval_ref": 〈승인번호JSON〉,
     "occurred_at": null,
     "received_at": "〈received_at〉"
   }
   ```

## 3. 미리보기, 전송, 재시도

처음에는 JSON을 `훑어보기(Quick Look)`에 연결해 확인한다. 빌린 아이폰에서도 다른 일반 단축어에 예시 본문을 넣은 사전을 만들고 `카드 이벤트 만들기`를 호출하면 실제 결제 없이 파싱을 확인할 수 있다. 자동 수신 검증 때는 다른 휴대폰의 번호를 **시연용 문자 자동화**에 등록해 합성 문자를 보내고, 푸시는 선택한 카드사 앱에서 실제 승인 알림을 받아야 한다. 잠근 상태에서도 각각 시험한다.

여행 웹의 **휴대폰 수집기 연결**에서 여행·결제자 토큰과 **전체 HTTPS 수신 URL**을 발급한 후 수동 구성한 단축어에 연결한다. 팀 공유본에는 예시 URL만 남긴다. 시연용 토큰은 개인 폰의 `나의 iPhone`에 여행별 파일로 따로 저장한다. 전송 단축어에서 그 파일을 선택해 `입력에서 텍스트 가져오기`로 읽고 인증 헤더의 변수로 사용한다. 토큰 파일은 아래 대기 폴더 밖에 두고, 공유·로그 출력 대상에서 제외한다.

1. `훑어보기` 대신 JSON 텍스트에 `이름 설정(Set Name)`으로 `〈event_id〉.json`을 지정한 뒤, `파일 저장(Save File)`으로 **나의 iPhone**의 이번 여행 전용 대기 폴더에 저장한다. 승인 알림 원문과 토큰은 파일에 넣지 않는다.
2. 전송용 일반 단축어 `카드 이벤트 보내기`를 만들고 저장한 **파일**을 입력으로 넘긴다. `URL` 동작에 서버가 지정한 전체 주소(형식 예시 `https://api.example.invalid/api/collector/events`)를 넣는다. `URL 콘텐츠 가져오기(Get Contents of URL)`에서 방법 `POST`, 헤더 `Authorization` 값 `Bearer 〈이 여행의 개인 토큰〉`, `Content-Type` 값 `application/json`, 요청 본문 `파일(File)` 값 **입력 JSON 파일**로 지정한다. 첫 실행은 폰을 잠금 해제한 상태에서 단축어가 요청하는 파일·도메인 접근을 허용한다. [Apple의 POST 요청 본문 설명](https://support.apple.com/en-lk/guide/shortcuts/apd58d46713f/ios)
3. 서버가 해당 `event_id`를 수락했음을 확인한 뒤 파일을 지운다. 시연 초반에는 응답 확인과 삭제를 수동으로 해도 된다. 응답이 없거나 연결이 끊기면 파일을 남기고, 같은 여행 토큰으로 `파일 선택 → 카드 이벤트 보내기`만 다시 실행한다. `카드 이벤트 만들기`부터 다시 실행하면 새 UUID가 생긴다. 이 구성의 오프라인 재시도는 수동이다.

문자와 푸시가 모두 오면 서버에 **이벤트 2개**가 간다. 서버는 토큰으로 여행·결제자를 결정하고, 승인번호 등으로 같은 구매임을 확인해 **지출 1개**에 연결한다. 결제 식별 근거가 부족하면 사용자 확인 대상으로 둔다. 환율·원화 금액은 서버에서 지출을 만들 때 붙인다.
