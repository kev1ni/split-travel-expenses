# 🌿 N빵트립 (NTrip)

[React 프론트엔드 실행](frontend/README.md) · [팀 API 명세](docs/API.md) · [Flask·Supabase 설정](database/README.md) · [모바일 수집기](card-collector/README.md)


### ✈️ 여행은 함께, 정산은 간편하게!

**N빵트립(NTrip)**은 친구들과 함께하는 여행에서 발생하는 경비를 간편하게 기록하고, 각자의 부담 금액을 자동으로 계산해 주는 **여행 경비 관리 및 정산 웹 서비스**입니다.

현금 지출은 직접 입력하고, 카드 지출은 결제 알림 메시지 파싱을 통해 등록할 수 있도록 설계했습니다.

여행 그룹별 지출 관리부터 친구 초대, 공동 경비 분담, 최종 정산까지 하나의 서비스에서 관리하는 것을 목표로 합니다.

## ✨ 주요 기능

### 🔐 1. 사용자 인증

- 회원가입 및 로그인
- 사용자 정보 관리
- 로그인 상태 유지
- 로그아웃

### 🧳 2. 여행 생성 및 관리

- 새로운 여행 생성
- 여행 이름, 장소, 기간 설정
- 참여 중인 여행 목록 조회
- 여행별 총지출 및 정산 상태 확인
- 여행 상세 정보 조회

### 👥 3. 친구 초대 및 멤버 관리

- 여행별 친구 초대
- 초대 코드 및 링크 공유
- 초대받은 여행 참여
- 여행 참여자 목록 조회
- 비회원 친구 등록 지원

### 💵 4. 현금 지출 관리

현금으로 결제한 내역은 사용자가 직접 입력합니다.

**입력 항목**
- 지출명
- 결제 금액 및 통화
- 결제 날짜
- 지출 카테고리
- 결제자
- 공동 부담자
- 메모

**분담 방식**
- 균등 분할
- 직접 금액 입력

### 💳 5. 카드 결제 메시지 파싱

카드 결제 알림 메시지에서 필요한 정보를 추출하여 지출 등록을 지원하는 기능입니다.

**주요 처리 과정**

1. 카드 결제 메시지 입력 또는 수신
2. 메시지 파싱
3. 결제 금액, 가맹점, 날짜 등 정보 추출
4. 사용자 확인 및 수정
5. 여행 지출 내역 등록

**추가 고려 사항**
- 중복 결제 알림 방지
- 구매 및 취소 구분
- 부분 취소 처리
- 원본 카드 알림 기록 관리

※ 실제 메시지 수신 방식과 파싱 API는 개발 및 협의 중입니다.

### 💰 6. 자동 N빵 정산

여행 참여자의 결제 금액과 실제 부담 금액을 기반으로 정산 결과를 계산합니다.

**예시**

| 참여자 | 결제 금액 | 부담 금액 |
|---|---:|---:|
| A | 90,000원 | 30,000원 |
| B | 0원 | 30,000원 |
| C | 0원 | 30,000원 |

**정산 결과**
- B → A : 30,000원
- C → A : 30,000원

### 📊 7. 지출 통계 및 환전 관리

- 여행별 총지출 확인
- 카테고리별 지출 통계
- 개인별 결제 및 부담 금액 비교
- 현금/카드 지출 구분
- 외화 결제 및 환율 적용 내역 확인
- 환전 기록 관리

## 🗄️ 데이터베이스 설계

현재 DB 설계에는 다음 8개 테이블이 포함되어 있습니다.

| 테이블 | 설명 |
|---|---|
| USERS | 사용자 계정 정보 |
| TRIPS | 여행 기본 정보 |
| TRIP_MEMBERS | 여행 참여자 정보 |
| EXPENSES | 여행 지출 내역 |
| EXPENSE_SPLITS | 지출별 참여자 부담 금액 |
| SETTLEMENTS | 정산 및 송금 정보 |
| CURRENCY_EXCHANGES | 환전 내역 |
| CARD_EVENTS | 카드 결제 알림 원본 및 연결 정보 |

### 설계 특징

**1. 중복 카드 결제 방지**

동일한 결제가 RCS 메시지와 앱 푸시로 각각 수신되더라도 여러 카드 알림을 하나의 지출에 연결할 수 있도록 설계했습니다.

**2. 구매 및 취소 내역 관리**

구매, 전체 취소, 부분 취소를 구분하여 실제 정산 대상 금액을 관리합니다.

**3. 비회원 참여 지원**

회원가입하지 않은 친구도 여행 참여자로 등록할 수 있도록 설계했습니다.

**4. 환율 적용 이력 관리**

해외 결제 시 적용된 환율 기준일을 기록하여 정산 금액의 근거를 확인할 수 있도록 설계했습니다.

## 🌿 Git 브랜치 전략

협업 과정에서 다음 브랜치 전략을 사용합니다.

```text
main
 |
 +-- develop
      |
      +-- feature/frontend
      +-- feature/backend
      +-- feature/database
      +-- feature/settlement
```

### 브랜치 역할

- `main` : 최종 완성 및 안정화 코드
- `develop` : 팀원 개발 코드 통합
- `feature/*` : 기능별 독립 개발

### 협업 규칙

1. 기능 개발은 `develop`에서 분기한 `feature/*` 브랜치에서 진행합니다.
2. 기능 구현 후 Pull Request를 생성합니다.
3. 코드 확인 및 리뷰 후 `develop`에 병합합니다.
4. 최종 테스트를 완료한 뒤 `main`에 병합합니다.
5. 의미 있는 단위로 커밋하고 변경 내용을 명확히 기록합니다.

### 커밋 메시지 예시

```bash
feat: add login page
feat: implement trip card UI
feat: add cash expense form
fix: resolve expense calculation error
style: update dashboard layout
docs: update README
```
